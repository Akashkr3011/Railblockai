DATE/TIMESTAMP: 2026-09-12

COMPONENT: Backend — Security (app/core/security.py + requirements.txt)

PREVIOUS BEHAVIOR:
Used passlib.CryptContext with bcrypt backend.
passlib 1.7.4 accesses bcrypt.__about__.__version__ during backend detection.
bcrypt 4.x removed the __about__ attribute, causing:
  ValueError: password cannot be longer than 72 bytes
during passlib's internal wrap-bug detection cycle.

NEW BEHAVIOR:
Replaced passlib.CryptContext with direct bcrypt.hashpw / bcrypt.checkpw calls.
Added bcrypt==4.0.1 pin to requirements.txt.
passlib removed from security.py imports entirely.

WHY MODIFIED:
passlib 1.7.4 is unmaintained and incompatible with bcrypt 4.x.
The bcrypt library's direct API (hashpw, checkpw, gensalt) is stable
and does not depend on passlib version detection.

FILES:
backend/app/core/security.py
backend/requirements.txt

COMPATIBILITY IMPACT:
Existing hashed passwords remain valid — bcrypt format is unchanged.
Any code importing pwd_context from security.py will break (none exists
outside security.py itself — the interface is hash_password/verify_password).

TEST RESULT:
test_security.py: ✅ 10/10 PASSED after fix
